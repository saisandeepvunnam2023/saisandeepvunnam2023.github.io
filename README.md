# saisandeepvunnam2023.github.io

Personal site for Sai Sandeep Vunnam. Static HTML generated by a small Python
build. No Node, no npm, no framework, no runtime dependencies.

**Read [CONTENT-NOTES.md](CONTENT-NOTES.md) before publishing.** It lists every
place your résumé files and your old site disagree, and every unresolved TODO.

---

## Quick start

```bash
python3 build.py --serve     # build into dist/ and serve it at localhost:8000
```

That is the whole toolchain. Python 3.9+ and nothing else.

Two other commands, needed less often:

```bash
python3 check.py             # structural checks on dist/ — run after every build
python3 optimize_images.py   # re-encode photographs (needs: pip3 install pillow)
```

## Why there is no React

The brief asked for React + Vite. This is static HTML instead, for three reasons
that all pointed the same way:

1. **Your professional claim is crawlable HTML.** Your name, role, availability
   and every project description are in the source of `index.html`. Nothing about
   your identity is rendered by JavaScript.
2. **Performance is a stated design requirement.** There is no framework runtime,
   no hydration, and no render-blocking stylesheet — the CSS is inlined. The
   entire first load is the HTML, one 90 KB font and one 82 KB hero image.
3. **This machine has no Node installed.** A build you cannot run is a build that
   rots. Python is already here and always will be.

Content still lives in structured data (`content/*.json`) exactly as asked — the
generator is just Python instead of a bundler.

## Project structure

```
build.py                 the static site generator — run this
check.py                 post-build checks: dead links, heading outline, alt text
optimize_images.py       photo pipeline + icons + social card (needs Pillow)

content/                 ALL editable content. You should rarely leave this folder.
  site.json              name, role, positioning, links, nav, SEO metadata
  projects.json          featured work + full case-study text
  skills.json            capabilities → technologies → the projects they appear in
  experience.json        roles, education, recognition
  story.json             photography, about and contact copy
  media.json             where your photograph originals live on disk
  media.derived.json     generated — sizes and blur placeholders. Do not edit.

builder/                 layout code. Python functions that return HTML.
  render.py              escaping, <picture>/srcset, shared bits
  layout.py              <head>, metadata, JSON-LD
  sections/              one module per section of the home page
  pages/                 home, case study, 404, and the SVG diagrams

static/
  css/                   14 files, concatenated and inlined at build time
  js/                    main.js + two lazily-imported modules
  fonts/                 self-hosted Archivo + Instrument Serif (latin subsets)
  media/                 generated image derivatives — committed
  files/                 your résumé PDF
  root/                  generated favicon.ico + apple-touch-icon.png

dist/                    build output. Never edit; it is deleted on every build.
```

## How to change things

### Turn the résumé back on

The résumé is currently hidden site-wide: `showResume` is `false` in
`content/site.json`, so no Résumé button is rendered in the nav, the hero, the
mobile menu or the contact section, and no PDF is copied into the build. That is
deliberate — a button leading to a placeholder is worse than no button.

To bring it back:

1. Put the real PDF at `static/files/Sai-Sandeep-Vunnam-Resume.pdf`
2. Set `"showResume": true` in `content/site.json`
3. `python3 build.py`

All four buttons reappear pointing at that one path. For a different filename,
change `links.resume` in the same file.

### Change wording anywhere

It is in `content/*.json`. Rebuild. There is no other copy of it.

**House style:** no em dashes in anything that renders. They are the clearest
tell that a machine wrote the sentence, and this site is meant to read like a
person. Use a full stop, a colon, or a comma instead. An en dash in a date range
(`Nov 2023 – Dec 2025`) is fine; that is just typography.

### Add a project

Add an object to `items` in `content/projects.json`. The required fields are
visible on every existing entry. Two of them matter:

- **`layout`** picks the composition. Use one of the five that exist:
  `shots` (a large lead screenshot plus a strip of detail shots), `covers` (a
  grid of published artefacts), `scale` (one large number plus detail),
  `split` (two-column argument), `pipeline` (horizontal stages — built, unused
  right now). Each needs its own data key — `lead`+`shots`, `covers`, `detail`,
  `splitPoints`, `stages` respectively. Copy the shape from a project already
  using that layout.
- **`caseStudy: true`** also generates `/work/<slug>/` from `caseStudySections`.
  Set it to `false` and the project appears on the home page only.

To invent a sixth layout, add a `_layout_*` function in
`builder/sections/work.py` and register it in the `LAYOUTS` dict at the bottom.

### Add a photograph

1. Add an entry to `images` in `content/media.json` with an `id`, a `role` of
   `gallery`, and the `src` path to the original.
2. Run `python3 optimize_images.py`.
3. Add an entry to `photography.photographs` in `content/story.json` using that
   same `id`, plus `title`, `caption`, `alt`, and a `span` of
   `full` / `wide` / `half` / `tall` — that is what drives the editorial grid.
4. `python3 build.py`

Write real alt text. It is how the photographs reach anyone using a screen reader,
and it is a ranking signal.

### Change the accent colour

`--accent` in `static/css/tokens.css`, plus its three companions
(`--accent-bright`, `--accent-soft`, `--accent-line`). It also appears in three
generated places: `FAVICON_SVG` in `build.py`, and `ACCENT` in
`optimize_images.py` (icons and the social card).

The current one is `#FF4A24` — darkroom safelight, the light you can work under
without destroying the image. It measures 5.8:1 against the background, so it
passes AA as text.

## Deploying to GitHub Pages

The repo is a **user site** (`saisandeepvunnam2023.github.io`), which Pages serves
from the repository root. This project builds into `dist/`, so pick one of these.

### Option A — GitHub Actions (recommended)

`.github/workflows/deploy.yml` is already set up. It builds with Python and
publishes `dist/` on every push to `main`. One-time setup:

1. Publish this repository as `saisandeepvunnam2023/saisandeepvunnam2023.github.io`.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions.**

That is it. After that, `git push` deploys.

### Option B — commit the built output

If you would rather not use Actions, build locally and publish `dist/` to a
`gh-pages` branch:

```bash
python3 build.py
git subtree push --prefix dist origin gh-pages
```

Then set **Settings → Pages → Source: Deploy from a branch → `gh-pages` / root**.

### Before the first deploy

- Put your real résumé PDF in `static/files/`.
- Set `links.linkedin` in `content/site.json`.
- Confirm `meta.siteUrl` in `content/site.json` — it is the base for the
  canonical tags, the sitemap and the Open Graph image URL.
- Run `python3 check.py` and make sure it reports no problems.

`dist/.nojekyll` is written automatically, which stops Pages running Jekyll over
the output and eating the underscore-prefixed paths.

## The interactive piece

### The skills readout

`static/js/skills.js`. Four capability columns, and one readout underneath that
fills in with whatever you point at — what the technology is used for, and which
project on the page it appears in.

It is a mirror and nothing more. Every technology's description and project link
already sit beside its name in the DOM; the module only changes *where* a
sighted pointer user sees them. On a phone, or with JavaScript off, that same
markup renders inline and the section becomes a plain readable list with nothing
missing. That is also why the readout is `aria-hidden` — a screen reader gets the
real markup rather than a duplicate.

One delegated listener on the container, not twenty-six on the names, and the
names are plain spans so they add no tab stops.

The hero photograph is shown plainly, with no interaction attached to it.

## Performance and accessibility notes

- CSS is inlined — 48 KB raw, ~9 KB over the wire, zero render-blocking requests.
- Fonts are self-hosted latin subsets, preloaded, `font-display: swap`.
- Every image ships AVIF → WebP → JPEG with `srcset`, an inline blur placeholder,
  and explicit `width`/`height` so nothing shifts as it loads.
- The hero preload offers the browser the same candidate list as the `<picture>`,
  so a retina screen does not download it twice.
- `skills.js` only downloads when the skills section is near the viewport;
  it is the only script beyond the 7 KB entry point.
- Reveal animations disconnect their observer once an element has been seen, and
  have a 2.5s CSS failsafe so content still appears if the module never loads.
- One `<h1>`, no heading-level skips, real landmarks, visible focus rings,
  a skills section that is fully readable without scripting, and a print stylesheet.

`check.py` enforces the structural half of that list on every build.

## A note on `builder/`

It used to be `site/`. That shadows Python's standard-library `site` module,
which is imported before your code runs, so `from site import render` silently
returned the wrong module. If you rename the folder again, do not pick a name
in the standard library.
